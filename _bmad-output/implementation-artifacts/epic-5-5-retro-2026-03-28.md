## What Went Well

### 1. First Showable End-to-End Pipeline (Effect Wow)
Khalil confirmed the demo is impressive and showable. For the first time, the complete flow is visible: email arrives → graph processes → Teams notification fires with working ERP link. The stabilization epic was an investment, not lost time.

### 2. Exemplary Quality Gate Discipline
Every story — including documentation and LinkedIn content stories — passed mypy strict, ruff, and the full unit test suite. 775 → 800 tests with zero regressions across all 10 stories.

### 3. Pre-Existing Bugs Surfaced by Stabilization
5 bugs that were invisible with toy data were discovered and fixed:
- `_ORDER_LINE_FIELDS` missing `order_id` (5.5.3)
- Teams URL fragment stripping breaking "Voir dans l'ERP" links (5.5.3)
- Route fallback silent drop to END when routing_decision is None (5.5.5)
- Compliance error silent continuation to END (5.5.5)
- `test_settings_default_values` pre-existing failure (5.5.10)

### 4. Pipeline Fully Wired End-to-End
Story 5.5.10 (unplanned, added mid-epic) closed the gap between the poller (Epic 2) and the graph pipeline (Epic 4). `QuoteRequestWorker` with `FOR UPDATE SKIP LOCKED` provides concurrency-safe autonomous processing.

### 5. Foundation Stories Pattern Confirmed (5th Time)
Stories 5.5.1-5.5.6 cleared the ground for everything else. This is now an established team signature.

### 6. Code Review as Safety Net #1 (5th Consecutive Epic)
Code review caught issues in every single story: mock usage (5.5.2), adapter bug (5.5.3), docstring defaults (5.5.4), path doc error (5.5.5), adapter count (5.5.6), French accents (5.5.7/8/9), batch lock duration (5.5.10).

### 7. Adapter Pattern Validated for Future-Proofing
Khalil raised the concern that switching from BGE-M3 to OpenAI/Anthropic embeddings in production could invalidate the work. Team confirmed the architecture is model-agnostic: the `EmbeddingAdapter` Protocol, RRF fusion, and search engine work on normalized scores. Changing embedding model = new adapter implementation + recalibration of thresholds, not a rewrite.

## What Didn't Go Well

### 1. "Treat as Pre-Existing" Pattern
`test_settings_default_values` was noted as "pre-existing, out of scope" in 8 consecutive stories (5.5.2 through 5.5.9) before being fixed in 5.5.10. The 19 E2E "failures" (Story 5.5.2) were a misdiagnosis that persisted for months — all tests actually passed when run with proper environment configuration.

### 2. Scope Creep on Infrastructure Stories
Story 5.5.3 ("populate test Odoo") grew to 17 files modified — adapter bug fix, redirect endpoints, config changes, catalog regeneration. The realistic data surfaced real bugs, but the story scope tripled.

### 3. Systematic French Accent Issues in AI-Generated Content
Stories 5.5.7, 5.5.8, and 5.5.9 all required accent corrections in code review: ~25, several more, and ~60+ respectively. AI-generated French text needs a systematic verification step.

### 4. GPU Bottleneck for Realistic-Scale Testing
50K product embedding on CPU takes 10-30 minutes. AMD RX 6600 is not CUDA-compatible. No GPU option available in dev. Story 5.5.4 proved it works at scale, but painfully.

### 5. asyncio.run Technical Debt Growing
15+ occurrences in 11 files, tracked across 3 consecutive retros. Never addressed until now.

## Significant Process Change for Epic 6+

### Co-Piloting Gate (Khalil Validation Required)

Khalil requested a fundamental change in operating mode starting Epic 6:

**GATE: Zero lines of code without prior Khalil validation.**

This applies to:
- **Before the story** → Khalil validates vision and exact scope
- **Before coding** → Khalil validates the concrete technical approach
- **After coding** → Review + Khalil confirms conformity with his vision
- **No exceptions** — including foundation stories

**Does NOT apply to:**
- Tests — Dana has autonomy on test design and implementation, provided exhaustive coverage with no blind spots

**Rationale:** Epic 6 (Memory, Learning & Feedback Loop) changes the nature of the product. Decisions about what the agent remembers, for how long, and with what weight are product decisions, not engineering decisions. The team's previous high autonomy worked for well-defined patterns (adapters, graph, notifications) but is not appropriate for a learning system.
