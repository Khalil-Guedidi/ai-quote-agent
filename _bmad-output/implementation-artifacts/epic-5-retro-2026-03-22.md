## What Went Well

### 1. Fire-and-Forget Pattern — Architectural Accelerator

Established in Story 5.1 and reused on 5.2, 5.3 without friction. Notification failure NEVER blocks the pipeline, NEVER sets state["error"]. Same accelerator effect as Epic 4's node pattern. Stories 5.2 and 5.3 required zero debugging — clean first-time implementations.

### 2. CLI Continues to Be the Standout Feature — 3rd Consecutive Epic

14 CLI commands total after Epic 5: `notify-test`, `batch-summary`, `weekly-report`, `manager-stats`, `scheduler-status` added. Khalil confirmed CLI as exceptional again. Combined with Teams webhook visual testing, the Project Lead now has two concrete interfaces to validate.

### 3. Root Cause Analysis Quality (Story 5.0b)

Flaky E2E test diagnosed correctly: fixture was semantically unambiguous (4 items for same project/delivery), not LLM non-determinism. The LLM was RIGHT not to split. Fix: semantically distinct fixture + temperature=0 on all ChatOpenAI instances. 5/5 consecutive runs passed. Lesson: question fixtures before blaming the tool.

### 4. Adapter Pattern Clean Design (Story 5.6)

Protocol stays `send_notification(payload) -> result` — no `format_card` in interface. Card formatting is channel-specific (Teams Adaptive Cards, Slack Block Kit, email HTML). LogAdapter as proof-of-concept proves multi-channel support. Factory routes by `settings.notification.channel`. Zero `isinstance` checks in core logic.

### 5. Notification UX — Consistent Tone & Structure

7 card types all follow structural consistency: accent bar → bot header "Q" → timestamp → content → actions. Casual French tutoiement throughout. Color-coded by confidence: green (ready), amber (proposals), red (escalation), blue (batch/reports). Alice confirmed it feels like a colleague, not a robot.

### 6. Intelligent Timing & Scheduling (Story 5.5)

Pure asyncio scheduler (no APScheduler/Celery). In-memory throttle (60s cooldown) + batcher (5+ in 10min → batch). Singleton factories via @lru_cache. Conditional startup in FastAPI lifespan. Minimal dependencies, clean design.

## What Didn't Go Well

### 1. CRITICAL: Review-Rejected Quotes Silently Dropped

`_route_after_compliance` in `agent/graph.py` routes review-rejected to END with no notification. Sophie never knows a quote was rejected by self-review. Discovered by Khalil during Story 5.6 manual testing. The only path to END without a notification. Khalil flagged as "un gros trou."

### 2. 19 E2E Tests in Silent Failure — The New CI/CD

19/22 E2E tests fail on DB setup errors. Treated as "pre-existing" in every story instead of blockers. Same pattern as CI/CD deferred across 3 retros in Epics 1-3. Tests exist but serve no purpose — decoration, not gate-keeping.

### 3. ERP de Test Odoo Vide — "Voir dans l'ERP" Mène Nulle Part

No products, no clients, no data in test Odoo. Every Teams notification's primary call-to-action ("Voir dans l'ERP") leads to an empty interface. The main user action after receiving a notification doesn't work.

### 4. Catalogue Miniature — Testing in a Toy World

All pipeline tests use 3-5 product fixtures. The 50K realistic catalogue (generated in Story 3.0c with ArcelorMittal patterns) exists but is unused beyond the jargon benchmark. No validation that search, scoring, or routing work at scale. Medium-confidence path couldn't be triggered manually with the miniature catalogue — not enough product variants to create genuine ambiguity.

### 5. Feature-First vs User-First Approach

5 epics built with feature-first approach: each story adds a technical capability tested in isolation. Result: a pipeline that works component by component but no complete user journey validated end-to-end. Sophie cannot: receive email → see Teams notification → click → see real quote in Odoo → validate. This journey does NOT exist today.

### 6. Copy-Paste Node Bug (Story 5.2)

`current_node` set to "notify" instead of "notify_proposals" in 3 locations. Caught by code review, invisible to tests. Copy-pasting a node and not updating routing constants is a systematic risk with the fire-and-forget pattern.

### 7. Build in Public Strategy Misaligned

14 LinkedIn posts in English targeting Franco-European industrial market. Text-only, no visuals (no screenshots, carousels, demos). Content disconnected from product value proposition. No landing page for market validation after 5 technical epics.

## Lessons Learned

1. **Feature-first ≠ user-first** — 768 tests and zero complete Sophie journey validated. Building capabilities in isolation creates an illusion of progress. The shift to user-first is the most important change in this project to date.
2. **E2E tests in silent failure are the new CI/CD** — same deferred-problem pattern. 19 tests failing for months, treated as noise. Tests must be gate-keepers: they pass or they block.
3. **The test environment must reflect reality** — miniature catalogue + empty ERP = lab validation, not field validation. The 50K catalogue exists and must be used. Sophie has 200K refs, thousands of clients, dozens of daily emails.
4. **Floating agreements get lost — 4th confirmation** — "CI green in DoD" promised in Epic 4, never done. Only items tracked as stories survive. This is permanent process.
5. **Code review remains safety net #1** — 4th consecutive epic. Bug current_node (5.2), hardcoded thresholds (5.4), DRY violations (5.5). Irreplaceable.
6. **Market validation cannot wait** — 5 technical epics without field signal. Landing page + francophone content strategy = strategic priority running in parallel.
7. **Graph path exhaustivity must be audited** — review-rejected was a 5th path to END that nobody inventoried. Every path must have: notification (or explicit justification) + E2E test coverage.
8. **Medium-confidence requires realistic data to trigger** — can't be tested with 3-5 products. Needs variant-rich catalogue where scoring genuinely hesitates.
9. **Foundation stories pattern confirmed across 4 epics** — Epic 2→3 (3.0a/b/c), Epic 3→4 (4.0a/b/c), Epic 4→5 (5.0a/b), Epic 5→5.5 (9 stories). Permanent pattern.

## Significant Discovery: Project Approach Pivot Required

### Feature-First → User-First Transition

Epic 5 retro surfaced systemic issues that go beyond bug fixes:

1. **No complete user journey exists** — system works component-by-component but not end-to-end
2. **Test environment is unrealistic** — miniature catalogue, empty ERP, broken E2E
3. **No market validation** — 5 epics without demand signal
4. **Content strategy misaligned** — wrong language, wrong format, wrong positioning

These issues affect ALL future epics, not just Epic 6. An Epic 5.5 (transition/stabilization) is required before proceeding.

### Impact on Epic 6

The current Epic 6 plan assumes:
- Reliable end-to-end pipeline → false (review-rejected gap, 19 E2E broken)
- Functional ERP for feedback loop (Story 6.4) → false (Odoo empty)
- Realistic data for calibration (Story 6.6) → false (miniature catalogue)

**Epic 6 CANNOT start until Epic 5.5 is complete.**
