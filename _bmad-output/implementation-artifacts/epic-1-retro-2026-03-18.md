## What Went Well

### 1. Adapter Pattern — Reusable and Solid

The Protocol + Implementation + DTOs + Factory pattern established in Story 1.4 became the team standard. Replicated 4 times (LLM, ERP, Email, Notification) without friction.

- `protocol.py` with `@runtime_checkable`, async methods, `health_check()`
- `models.py` with Pydantic DTOs
- `__init__.py` with `get_*_adapter()` factory (`@lru_cache`)

### 2. Quality Gates — Zero Compromise

mypy --strict from day 1, ruff without exception, 95% coverage. Upfront investment clearly prevented regressions. Each story added tests without breaking existing ones.

- Story 1.1: 13 tests -> Story 1.8: 68 tests (organic progression)
- 0 regressions across the entire epic

### 3. Health Check Extensibility

The `/health` endpoint with incremental service addition worked exactly as designed. Went from 1 service (database) to 5 without refactoring. 30s TTL caching was critical for LLM cost management.

### 4. Async Throughout

Entire stack is async. `asyncio.to_thread()` for wrapping sync stdlib calls (xmlrpc, imaplib) — clean and performant. No sync-to-async debt to clean up later.

### 5. CI/CD Pipeline Operational from Day 1

Sequential fail-fast pipeline (lint -> format -> type-check -> test -> Docker build) with uv caching. All 68 tests green, Docker multi-stage build validated.

## What Didn't Go Well

### 1. Pydantic + Mocking Friction (Story 1.4)

ChatOpenAI is a Pydantic model. `patch.object` on instances fails because Pydantic intercepts `__setattr__`/`__delattr__`. Required class-level patching instead.

### 2. Health Endpoint Cascade Effect (Stories 1.4, 1.5, 1.6)

Each new service added to the health endpoint broke existing tests (missing mock for new dependency). Resolved by extracting test helpers to `conftest.py` in Story 1.5.

### 3. Runtime vs Dev Dependency Misclassification (Story 1.7)

httpx was classified as dev dependency but TeamsAdapter used it at runtime. Discovered only during Docker build in Story 1.7.

### 4. Integration Test Segregation (Story 1.2)

Integration tests broke unit tests due to fixture conflict (`env_vars` autouse overwriting real `DATABASE__URL`). Required separate `tests/integration/` directory with dedicated conftest.

### 5. FastAPI Dependency Override Gotcha (Story 1.3)

`Annotated[AsyncSession, Depends(...)]` breaks `dependency_overrides` in tests (FastAPI returns 422). Required keeping standard `Depends()` pattern with `noqa: B008`.

## Lessons Learned

1. **Lazy Initialization > Eager Connection** — Store settings, connect at health_check. Safer and more testable.
2. **Health Check Caching is Mandatory** — 30s TTL prevents costly LLM calls and webhook floods.
3. **Separate Integration from Unit Tests Early** — Dedicated conftest, separate directory. Not optional.
4. **Audit Runtime Dependencies at Each Story** — httpx misclassification could have broken Docker build later.
5. **Pydantic Models Need Class-Level Mocking** — Instance-level patching fails silently.
6. **Test Helpers in conftest Scale** — Extracting `create_test_app`, `mock_healthy_adapter` eliminated duplication.
7. **PEP 695 Generics > typing.Generic** — Cleaner for Pydantic models.
8. **BaseHTTPMiddleware for True Global Exception Catching** — `app.exception_handler(Exception)` is insufficient.

## Established Patterns (Carry Forward)

### Adapter Pattern
```
protocol.py  -> @runtime_checkable Protocol, async methods, health_check()
models.py    -> Pydantic DTOs
{impl}.py    -> Business logic implementation
__init__.py  -> get_*_adapter() factory with @lru_cache
```

### Health Check Pattern (30s TTL)
```python
_last_health: ServiceHealth | None = None
_last_health_time: float = 0.0
_HEALTH_CHECK_TIMEOUT = 5.0
_CACHE_TTL = 30.0
```

### Async Wrapping (sync stdlib)
```python
result = await asyncio.to_thread(sync_function, arg1, arg2)
```

### Test Infrastructure
- Unit tests: `tests/unit/` with shared `conftest.py` helpers
- Integration tests: `tests/integration/` with dedicated conftest
- Async testing: `httpx.AsyncClient` + `ASGITransport(app=app)`
- Dependency overrides for adapter/database mocks

### Error Response Format
```json
{"error": {"code": "...", "message": "...", "detail": "..."}, "meta": {"timestamp": "ISO8601"}}
```
