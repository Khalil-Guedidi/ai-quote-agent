## What Went Well

### 1. Node Pattern Uniforme — Accélérateur sur 8 Stories

The async function + Pydantic DTOs + CLI command + unit tests pattern was established in Story 4.1 and reused without friction across Stories 4.2–4.8. Each story was predictable in structure, reducing cognitive overhead and enabling consistent quality.

### 2. Fail-Safe Systématique — Zero Approval by Default

Every node implements safe failure behavior: classification fallback to "complex", scoring fallback to tier="low" (escalation), self-review fallback to approved=False, compliance fallback to is_compliant=False. No node ever approves by default on error. This is a coherent security posture across the entire pipeline.

### 3. CLI as Interface of Truth — 9 Commands, Full Visibility

Born from the Epic 3 retro lesson ("Project Lead must see the product"), Epic 4 delivered 9 CLI commands: `search`, `classify`, `reason`, `score`, `review`, `compliance`, `erp-read`, `draft-create`, `process`. Each step of the pipeline is individually testable. The `--json` flag on every command enables scripted testing. Khalil confirmed the CLI is the standout feature of this epic.

### 4. Jargon Dictionary Removed — Data-Driven Decision (Story 4.0c)

Benchmark: 96% pass rate with dictionary enabled, 96% with dictionary disabled — 0% delta. BGE-M3 handles all industrial jargon (inox, DN, PN, Ø, lg, TB, RD) natively. The dictionary was removed entirely, restoring the zero-preprocessing product vision. 24 jargon-related tests removed.

### 5. CI/CD Resolved After 3 Retros (Story 4.0a)

ML dependencies separated into optional group. 363 tests run in CI without sentence-transformers/PyTorch. 11 pre-existing mypy errors, 17 ruff errors, and 30 formatting issues fixed. The pipeline that was broken since Epic 1 is now functional.

### 6. Input Isolation Layer 2 — Consistent Security

`<<<UNTRUSTED_*>>>` delimiters applied in EVERY LLM call across Stories 4.1, 4.2, 4.3, 4.4, 4.5. Security posture is coherent and consistent.

## What Didn't Go Well

### 1. CI Green but Not Verified — Lint Errors Introduced Post-Fix

Stories 4.2 and 4.3 introduced 3 ruff lint errors (I001 import sorting, 2x F401 unused imports) in test files. The CI pipeline correctly flagged them, but nobody verified CI results before marking stories as done. The pipeline was working; the process of checking it was not.

Fixed during this retrospective (commit `b8722ce`).

### 2. Test E2E Flaky LLM — Second Consecutive Retro Unreported

The flaky LLM splitting E2E test from Story 3.3 was flagged in the Epic 3 retrospective and not addressed during Epic 4. This is the same pattern as CI/CD was before — a problem deferred across retrospectives until it compounds.

### 3. asyncio.run() Fragile Pattern in 9 CLI Commands

Identified in Story 4.6 code review (M2). All CLI commands use `asyncio.run()` which crashes if an event loop already exists. Affects 9 commands. Deferred as it doesn't impact current usage but will grow with Epic 5 adding more commands.

### 4. Code Review HIGH Issue (Story 4.8) Not Caught by Tests

The `draft_node` used a wrong ID as placeholder when `odoo_id` is None. Caught by adversarial code review, not by automated tests. Third consecutive epic where code review catches critical issues invisible to tests.

## Lessons Learned

1. **The node pattern is an accelerator** — established in 4.1, reused on 7 stories without friction. Predictable structure reduces cognitive overhead. Apply to Epic 5 notification adapters.
2. **Data-driven decisions protect the product vision** — the jargon benchmark (96%, delta=0) eliminated an architectural regression with zero ambiguity. Apply systematically to future architectural questions.
3. **CI must be verified, not just running** — investing in a pipeline without checking its results renders the investment useless. "CI green = done" is the correction.
4. **Adversarial code review is irreplaceable** — 3rd consecutive epic catching critical issues invisible to tests (4.8 draft_node ID, 4.1 fallback_complexity typing). Continue investing in review quality.
5. **Action items tracked as stories work; floating agreements don't** — 3rd epic confirming this pattern. 4/6 completed (all stories), 1/6 not addressed (floating item). Permanent process.
6. **Foundation stories pattern is proven across 3 epics** — Epic 2→3 (3.0a/b/c), Epic 3→4 (4.0a/b/c), Epic 4→5 (5.0a/b). The pattern is permanent.
7. **The Project Lead seeing the product is non-negotiable** — CLI in Epic 4 (4.0b), webhook Teams test in Epic 5 (5.0a). Every epic must have a manually testable flow.
8. **Fail-safe as first principle** — errors trigger escalation/rejection, never approval. Coherent across all 7 agent nodes.
