## Structure du post

### Accroche (1-2 phrases)

{Un résultat surprenant, une découverte contre-intuitive, ou une question qui arrête le scroll. Accompagne le visuel. Le lecteur doit se dire "tiens, c'est intéressant".}

### Problème (2-3 phrases)

{Quel défi industriel B2B est adressé ? Cadrer comme un problème métier réel. Le lecteur (directeur industriel, responsable achats) doit hocher la tête en se reconnaissant. Être spécifique : chiffres, contraintes, contexte domaine.}

### Solution / Insight (3-5 phrases)

{Ce qu'on a construit ou découvert. Niveau technique accessible. Exemples concrets. Nommer les outils/techniques mais expliquer pourquoi on les a choisis, en termes simples.}

### Métrique / Preuve (1-2 phrases)

{Montrer un résultat mesurable. Précision, latence, couverture, comparaison avant/après. Les chiffres construisent la crédibilité.}

### Question finale (1-2 phrases)

{Terminer par une question ouverte pour l'audience non technique. Directeurs industriels, responsables achats, managers PME. Pas une question d'ingénieur. Pas un pitch commercial. Un vrai sujet de conversation.}

## Checklist de formatage

- [ ] Longueur totale : 120-200 mots
- [ ] Rédigé en français (termes techniques anglais en ligne seulement)
- [ ] Asset visuel prêt (carousel, screenshot, schéma ou démo)
- [ ] Le visuel est compréhensible sans lire le texte
- [ ] Pas de noms de clients ni d'info confidentielle
- [ ] Toutes les données viennent du code et des métriques de ce repo
- [ ] Expérience professionnelle cadrée comme expertise domaine, pas travail client
- [ ] Au moins un chiffre ou une métrique concrète
- [ ] Finit par une question pour audience non technique
- [ ] Ton humain, familier, expert-qui-simplifie
- [ ] Pas de tirets longs, pas de "C'est X, pas Y"
- [ ] Pas de buzzwords corporate
- [ ] Hashtags (4-5 max) : mix français + anglais, inclut #BuildInPublic

---

## Approche visual-first

Le visuel est l'élément principal du post. Le texte accompagne et contextualise.

**Principe :** Si quelqu'un ne fait que regarder le carousel ou le screenshot sans lire le texte, il doit comprendre l'essentiel du message.

**Guide par type de post :**
- **Post process/architecture** : Carousel multi-slides (flux étape par étape, schéma simplifié)
- **Post résultat/code** : Screenshot annoté (terminal, sortie, interface)
- **Post design système** : Schéma/diagramme (épuré, lisible, légendes courtes)
- **Post démo** : GIF ou vidéo courte (CLI en action, flux email-vers-devis)
